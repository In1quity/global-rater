# Конфигурация отдельных вики

Начиная с 3.4.0, правила конкретной вики хранятся в JSON-профиле, а подписи интерфейса — в словаре переводов. Для добавления вики или изменения названий её шаблонов не нужно добавлять условия в JavaScript.

## Файлы и выбор профиля

```text
rater/data/
  default.json       # Общие нейтральные значения и настройки загрузки
  enwiki.json        # Английская Википедия
  ruwiki.json        # Русская Википедия
  <wgDBname>.json    # Профиль дополнительной вики
i18n/
  en.json            # Английский интерфейс
  ru.json            # Русский интерфейс
  <language>.json    # Дополнительный язык интерфейса
```

Имя профиля совпадает с `mw.config.get('wgDBname')`, например `ruwiki`. При отсутствии такого профиля проверяется текущий сервер по `wiki.servers`. Если совпадения нет, используются нейтральные значения: без английских категорий, оценок, блока проектов и ORES.

Язык интерфейса определяется отдельно, по `wgUserLanguage`. Поэтому русский интерфейс на енвики использует русские подписи и английские правила шаблонов. `editSummaryLanguage` задаёт язык комментария правки независимо от интерфейса. Переводы отсутствующих сообщений берутся из `i18n.fallbackLanguage`.

При сборке автоматически подключаются все JSON-файлы из этих двух каталогов. Профили и словари включаются в JavaScript, а их отдельные копии появляются в `dist/rater/data/` и `dist/i18n/`.

## Порядок применения настроек

1. `rater/data/default.json`.
2. Профиль текущей вики.
3. `window.RATER_CONFIG`, если задан объект; иначе JSON из `window.RATER_CONFIG_URL`, если задан URL.
4. Сохранённые пользовательские предпочтения при открытии интерфейса, например режим автоматического оборачивания.

Объекты объединяются по полям; массивы заменяются целиком. Пустая строка отключает категорию, пустой массив — соответствующий список правил. Отсутствующее поле наследуется. Внешние конфиги старого формата продолжают работать. Если одновременно заданы `RATER_CONFIG` и `RATER_CONFIG_URL`, используется объект.

## Как добавить новую вики

1. Узнайте `wgDBname` в консоли браузера на этой вики. Создайте `rater/data/<wgDBname>.json`; начните с необходимых полей нейтрального профиля. Копировать английский профиль целиком стоит только при совпадении правил шаблонов.
2. Найдите реальные категории баннеров, блок проектов и поддерживаемые параметры. Проверьте исходный код шаблонов, документацию, TemplateData и перенаправления. Категории указываются с пространством имён; шаблоны и их исключения можно указывать без него.
3. Задайте оценки, важности, имена параметров и их алиасы. Определите отдельно отображаемую и сохраняемую запись уровней.
4. Для блока перечислите только поддерживаемые параметры в `shell.parameters`. Этот список используется вместо обычной схемы баннера и не наследует её дополнительные поля.
5. В `defaultParameterData` перечислите поля обычных проектов на случай отсутствия TemplateData. `suggested` и `autovalue` используйте только для полей, действительно поддерживаемых такими шаблонами.
6. Добавьте новые подписи в `i18n/<language>.json`, а в схемах параметров укажите `labelKey` и `descriptionKey`. Переводы не добавляются в JavaScript. Существующие сообщения можно использовать повторно.
7. Добавьте регрессионные примеры для правил этой вики: изменение оценки и важности, вложенный блок, удаление и повторное оборачивание, отсутствие TemplateData. Проверьте `npm run lint`, `npm run test:ooui`, `npm run build` и собранный скрипт на тестовой странице обсуждения.

Пример минимального профиля для вики с индивидуальными оценками:

```json
{
  "wiki": { "servers": ["https://example.org"] },
  "categories": { "withRatings": "Category:Local project banners" },
  "bannerNamePrefixes": ["Local project "],
  "bannerDefaults": {
    "classes": ["I", "II", "III", "IV"],
    "importances": ["high", "medium", "low"],
    "classParamName": "quality",
    "importanceParamName": "priority",
    "lowImportance": "low",
    "stubClasses": ["IV"]
  },
  "assessmentParameters": {
    "class": ["quality"],
    "importance": ["priority"]
  },
  "shellTemplate": "Local project shell",
  "shell": {
    "autoCreate": false,
    "minProjects": 3,
    "classLocation": "banners",
    "parameters": [{ "name": "1" }]
  },
  "classFormat": "arabic",
  "classDisplayFormat": "roman",
  "editSummaryLanguage": "en",
  "defaultParameterData": {
    "quality": { "suggestedvalues": ["I", "II", "III", "IV"], "labelKey": "parameter-class-label" },
    "priority": { "suggestedvalues": ["high", "medium", "low"], "labelKey": "parameter-importance-label" }
  }
}
```

Названия и значения в примере условные: их нужно заменить реальными данными вики. Имя нового файла автоматически становится идентификатором профиля; отдельный реестр в JavaScript не требуется.

## Основные группы полей

| Поля | Назначение |
| --- | --- |
| `wiki.servers` | Список серверов для резервного определения вики. Основной идентификатор — имя файла и `wgDBname`. |
| `categories` | Категории для поиска баннеров: `withRatings`, `withoutRatings`, `wrappers`, `notWPBM`, `inactive`, `wir`. Каждое значение — одно название категории или `""`. Подкатегории обходятся рекурсивно; продолжения ответов API обрабатываются. |
| `bannerNamePrefixes`, `bannerExclusions` | Префиксы проектов и служебные шаблоны, которые нужно исключать из предложений. Блок и его алиасы исключаются отдельно автоматически. |
| `bannerDefaults` | Доступные оценки и важности, их стандартные параметры, алиасы значений, низкая важность, уровни заготовок и списков. |
| `customBanners` | Особые наборы оценок и важностей для отдельных шаблонов. |
| `assessmentParameters.class`, `.importance` | Кандидаты имён или алиасов параметров из TemplateData; порядок определяет приоритет. Это позволяет использовать `уровень`, `quality` и другие локальные названия. |
| `defaultParameterData` | Резервная схема обычного баннера без TemplateData. Поля могут иметь `aliases`, `suggestedvalues`, `allowedValues`, `required`, `suggested`, `autovalue`, `labelKey`, `descriptionKey`. |
| `shellTemplate`, `shell.aliases`, `shell.parameters` | Название блока, дополнительные названия и его полная схема параметров. Перенаправления блока также запрашиваются у вики. |
| `shell.autoCreate`, `.minProjects` | Создавать блок всегда при наличии проектов либо начиная с заданного количества. `false` и `null` отключают автоматическое создание. |
| `shell.classLocation`, `.classParamName` | `"banners"` сохраняет оценки в отдельных проектах; `"shell"` — в существующем блоке, а при его отсутствии в проектах. Во втором случае параметр оценки должен присутствовать в `shell.parameters`. |
| `shell.biographyBannerNames`, `.biographyParameters` | Необязательные имена биографических баннеров и переносы `{ "source": "...", "target": "...", "normalise": "yesno" }`. Перенос не добавляет поле, отсутствующее в схеме блока. |
| `classFormat`, `classDisplayFormat` | Формат сохраняемых значений и подписей списка: `"native"`, `"roman"` или `"arabic"`. Буквенные оценки сохраняются. |
| `subjectPageCategories` | Прямые категории страницы: `disambig`, `stub`, `goodArticle`, `featuredArticle`, `featuredList`. Нужны категории, в которые входят сами статьи. |
| `subjectPageCategoryPatterns`, `subjectPageTitlePatterns` | Дополнительные регулярные выражения для признаков статьи и названий списков. Обратный слеш в JSON экранируется: `\\s`. При наличии шаблонов категорий запрашиваются все категории страницы. |
| `ores` | Включение прогнозов, идентификатор вики, верхние уровни, базовый класс и оценки, пригодные для автозаполнения. Отключено в нейтральном профиле. |
| `ratingDetection` | Необязательная проверка расширенных оценок по категориям разобранного шаблона: страница разбора и фрагменты названий категорий с `{value}`. Если не настроена, используются данные профиля и TemplateData. |
| `booleanAliases`, `substitution` | Локальные алиасы булевых значений, префикс подстановки и распознаваемые алиасы без завершающего двоеточия. |
| `sortKey` | Необязательный параметр сортировки биографических баннеров и регулярные выражения суффиксов имени. |
| `talkPageWarnings`, `autostartTemplatePatterns` | Баннеры, требующие предупреждения при создании пустой страницы обсуждения, и дополнительные шаблоны для автозапуска. |
| `editSummaryLanguage`, `script` | Язык комментария правки, ссылки справки/обсуждения и подпись скрипта. `{version}` заменяется версией сборки. |
| `i18n` | Резервный язык и URL словарей, которые отсутствуют в сборке. |
| `defaultPrefs` | Начальные пользовательские предпочтения; сохранённые значения имеют приоритет. |

Предпочтение `shellCreation` допускает `"wiki"`, `"never"`, `"always"`, `"2"`, `"3"`. Существующий блок сохраняется, пока его явно не удалят в редакторе. После удаления доступна кнопка повторного оборачивания.

Настоящая TemplateData имеет приоритет над резервной схемой. Неизвестные существующие параметры сохраняются. Старые резервные записи TemplateData не используются, а список проектов обновляется при изменении настроек категорий. Добавлять параметры к URL для обхода HTTP-кеша не требуется.

## Проверенные категории рувики

Названия проверены через API Википедии и связи Викиданных 13 октября 2026 года. Связь Викиданных помогает найти кандидата, но не гарантирует одинаковую структуру и назначение категорий.

| Данные | Категория рувики | Связь Викиданных и выбор |
| --- | --- | --- |
| Баннеры проектов | [Категория:Шаблоны проектов:Баннеры](https://ru.wikipedia.org/wiki/Категория:Шаблоны_проектов:Баннеры) | [Q7132843](https://www.wikidata.org/wiki/Q7132843): связана с `Category:WikiProject banner templates`, общей категорией баннеров енвики. При проверке — 257 шаблонов. |
| Неоднозначность | [Категория:Страницы значений по алфавиту](https://ru.wikipedia.org/wiki/Категория:Страницы_значений_по_алфавиту) | [Q9700479](https://www.wikidata.org/wiki/Q9700479): связана с `Category:All disambiguation pages`. |
| Заготовки | [Категория:Незавершённые статьи](https://ru.wikipedia.org/wiki/Категория:Незавершённые_статьи) | [Q2944440](https://www.wikidata.org/wiki/Q2944440): связана с `Category:Stubs`, но не является плоским списком всех заготовок. Профиль также распознаёт прямые категории по выражению `^Категория:Незаверш[её]нные статьи(?:\\s|$)`. |
| Хорошие статьи | [Категория:Википедия:Хорошие статьи по алфавиту](https://ru.wikipedia.org/wiki/Категория:Википедия:Хорошие_статьи_по_алфавиту) | [Q9477626](https://www.wikidata.org/wiki/Q9477626): английская ссылка отсутствует; выбрана проверенная локальная категория самих статей. |
| Избранные статьи | [Категория:Википедия:Избранные статьи по алфавиту](https://ru.wikipedia.org/wiki/Категория:Википедия:Избранные_статьи_по_алфавиту) | [Q9465907](https://www.wikidata.org/wiki/Q9465907): категория самих статей. Связанный с английской общей категорией [Q4387444](https://www.wikidata.org/wiki/Q4387444) ведёт к русской объединяющей категории и для проверки членства статьи не подходит. |
| Избранные списки | [Категория:Википедия:Избранные списки по алфавиту](https://ru.wikipedia.org/wiki/Категория:Википедия:Избранные_списки_по_алфавиту) | [Q8101833](https://www.wikidata.org/wiki/Q8101833): связана с `Category:Wikipedia featured lists`. |

У английских категорий баннеров с оценками ([Q8920396](https://www.wikidata.org/wiki/Q8920396)), без оценок ([Q8920397](https://www.wikidata.org/wiki/Q8920397)), обёрток ([Q65735426](https://www.wikidata.org/wiki/Q65735426)), неактивных проектов ([Q8543529](https://www.wikidata.org/wiki/Q8543529)) и Women in Red ([Q125441423](https://www.wikidata.org/wiki/Q125441423)) русские ссылки отсутствуют. Поэтому профиль рувики использует общую реальную категорию баннеров, а остальные группы оставляет пустыми. Служебные `Статья проекта`, `Уровень статьи` и сам блок исключаются из предложений.

Викиданные проверяются при подготовке профиля; во время работы Rater к ним не обращается. Категории и правила можно исправлять явно, не завися от изменения межъязыковых связей.

## Публикация и внешние JSON

Обычная публикация — пересобрать скрипт после изменения JSON и обновить `User:Iniquity/rater-core.js` и `User:Iniquity/rater.js` на MediaWiki.org. Профили уже входят в core. Исходные адреса публикации сохранены.

Чтобы поддерживать отдельные конфиги непосредственно на вики, копию `dist/rater/data/ruwiki.json` можно публиковать как `User:Iniquity/rater/data/ruwiki.json`. Для других разделов меняется только имя файла. Создание такой страницы само по себе не подключает её: нужно задать `RATER_CONFIG_URL` перед импортом скрипта.

Локальная JSON-страница на той же вики:

```javascript
window.RATER_CONFIG_URL = '/w/index.php?title=User:YOUR_USERNAME/rater/data/ruwiki.json&action=raw&ctype=application/json';
```

Для центральной страницы на MediaWiki.org используйте API с `origin=*`. Загрузчик понимает как обычный JSON, так и содержимое страницы из ответа API. `{wiki}` заменяется текущим `wgDBname`:

```javascript
window.RATER_CONFIG_URL = 'https://www.mediawiki.org/w/api.php?action=query&format=json&formatversion=2&prop=revisions&rvprop=content&rvslots=main&origin=*&titles=User:Iniquity/rater/data/{wiki}.json';
mw.loader.load('https://www.mediawiki.org/w/index.php?title=User:Iniquity/rater.js&action=raw&ctype=text/javascript');
```

JSON-страницу нужно создать и наполнить до подключения URL. Если её невозможно загрузить, встроенный профиль сохраняется. Для новых профилей без встроенной копии заполните все необходимые поля во внешнем JSON.

В текущем `common.js` Solidest уже указан старый `User:Iniquity/config.json` на рувики. Он продолжает работать и переопределять встроенные значения. Для проверки нового встроенного профиля уберите это назначение URL; для проверки новой отдельной страницы замените его на её адрес после публикации JSON. Сам импорт персонального `Участник:Solidest/rater.js` можно оставить.

Отдельные копии словарей в `dist/i18n/` предназначены для публикации по адресу `i18n.baseUrl`, если требуются переводы, не вошедшие в сборку. Английский и русский словари уже включены в сборку.
